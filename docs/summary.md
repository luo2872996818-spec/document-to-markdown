# 项目总结：Document to Markdown

## 完成情况

已完成一个本地运行的批量文档转换工具，支持：

- 电子版 PDF
- DOCX
- XLSX、XLSM、XLS
- CSV、TSV
- 多文件批量转换
- Markdown 在线预览
- 单个 Markdown 下载
- ZIP 打包下载
- 转换报告
- 固定输出目录
- 中文文件名和中文内容

## 主要成果

- 网页界面使用 Streamlit。
- 文档解析使用 MarkItDown、PyMuPDF4LLM、openpyxl 和 xlrd。
- 程序运行时不调用在线 AI，全部在本机完成。
- 单文件转换失败不会影响同一批次中的其他文件。
- 每次任务保存到独立的 `output/run-时间戳` 目录。
- 自动化测试共 22 项，全部通过。
- 使用真实 DOCX、PDF 和 XLSX 文件完成 7 个文件的批量测试，全部成功。

## 遇到的问题

### Streamlit 从其他目录启动时报错

程序曾出现 `ModuleNotFoundError: No module named 'src'`。原因是启动目录不同，Python 找不到项目包。解决方法是在入口文件中根据 `__file__` 自动计算项目根目录并加入模块搜索路径。

### Excel 尺寸元数据错误导致丢列

用户的 Excel 实际包含 7 列，但文件内部尺寸信息错误，openpyxl 只读模式只读取了第一列。解决方法是使用普通读取模式，并增加错误尺寸回归测试。

### 公式没有缓存结果

部分 Excel 公式没有保存计算结果，读取后成为空单元格。解决方法是同时读取公式，数据值为空时保留公式文本。

### UTF-8 BOM 残留

带 BOM 的 CSV 会把隐藏字符带进第一个表头。解决方法是读取前三个字节，优先识别 UTF-8 BOM。

## 学到的内容

- 文档格式虽然都能显示内容，但内部结构差异很大。
- PDF 是固定版式，Word 是文档结构，Excel 是二维数据，不能用同一种方式处理。
- 程序运行时不一定要使用 AI，成熟解析库更适合可重复任务。
- 错误隔离、重名处理和固定输出目录是批量工具的重要功能。
- 测试应覆盖真实文件和异常文件，而不仅是正常样本。

## 已知限制

- 扫描版 PDF 不进行 OCR。
- DOC 旧版 Word 文件暂不支持。
- 标准 Markdown 无法完整表达合并单元格、颜色和复杂页面排版。
- 复杂 PDF 表格的质量取决于原始 PDF 的结构。
- Excel 公式没有缓存值时输出公式文本，不进行计算。
